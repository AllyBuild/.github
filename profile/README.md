## One team. You included.

AllyBuild puts you **inside** the team, not above it. Coach dsh agents in conversation, keep the keys to risky moves, and open-source the whole setup only if and when you want to.

Every project runs on a bench of dsh agents, and you join them as the human member: same workspace, same conversation, same goal.

- **🧑‍💼 The human teammate — coach and gatekeeper.** Talk to agents in the same thread they work in, answer questions mid-run, approve what matters, and rate the result. The team calibrates to your standard.
- **🤖 dsh agents — hired, not prompted.** Each agent joins with a name, a model, its own skills, and the meta-tasks it owns. Every agent is a native dsh process in an isolated sandbox, wired into the shared workspace.
- **🧠 Remembers the standard.** Agents draw on shared skills and memory, so yesterday's feedback shapes tomorrow's run.
- **📋 A real board for real runs.** Tasks move through phases on a shared board. When a run needs a human call, the card parks in _needs approval_ until you decide.

## The loop: Assemble. Collaborate. Calibrate. Publish.

1. **Assemble the team** — hire agents: pick the model, wire the skills, assign the meta-tasks they own. A project, its workspace, and its agents are one package from day one.
2. **Work side by side** — hand out tasks. Agents run in their sandbox and pull you in when a question or a gate needs a human. Conversations, tasks, and approvals live in one thread, not three tools.
3. **Calibrate to your bar** — rate the work and correct the course. Feedback lands in skills and memory, so the team drifts toward how you work.
4. **Publish the whole team** — private by default. When you choose to publish, you hand over the running setup: agents, skills, scripts, schedules — not a screenshot.

## Share the running team, not a template

A prompt is a sentence. A published team is a **system**: the roles, the environment, the schedules, and the learned skills. Forkers get the whole loop, not a hint.

```text
support-copilot/
├── agents/       # the roster: model, tools, and skills per agent
├── task_types/   # the job descriptions: phases, params, full scripts
├── skills/       # the playbook agents draw from, in the open
├── crons/        # the rhythm: what runs on a schedule
└── services/     # the infrastructure that stays up
```

- **Readable end to end** — no black boxes. Audit how a team reaches its results before you trust it with yours.
- **Fork runs on day one** — forking rebuilds the full configuration as a project in your workspace. It runs; it is not a walkthrough.
- **Private by default** — publishing is optional. Only the project configuration goes public; never your execution history or workspace files.
